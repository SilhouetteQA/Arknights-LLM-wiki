# 会话总结 — 2026-06-27-2 (Agent Pipeline 系统性优化)

## 任务

基于 qa_log.jsonl 14 条真实对话对 Phase 3 Agent 全 pipeline 做端到端诊断和修复。

## 诊断方法

逐条分析 qa_log 中的路由实体、检索来源、回答质量，按 5 个 pipeline 阶段分类缺陷：
1. 意图识别 → 2. 实体提取 → 3. 复杂度路由 → 4. 多源检索 → 5. 回答合成

## 修复清单

### P0 致命缺陷

| 缺陷 | 根因 | 修复 |
|------|------|------|
| search_dialogue 崩溃 `'list' object has no attribute 'get'` | `_order.json` 是纯数组，`data.get("lines")` 失败 | `isinstance(data, dict)` 类型守卫 |
| 实体提取噪声（5213 WikiStore 全量子串匹配） | "相变临界"匹配到"罗德岛""乌萨斯""切尔诺伯格"等无关实体 | 砍掉 WikiStore 扫描，改为 identity_map + operators + chapter_timeline 三层精确提取 |
| 章节+角色组合检索失败（"相变临界中凯尔希怎么样"→回答"未提及"） | 事件搜索只用 entity=凯尔希 没有 chapter=相变临界 过滤 | 章节感知检索：自动识别实体中的章节名，事件按章节过滤 |

### P1 高优先缺陷

| 缺陷 | 根因 | 修复 |
|------|------|------|
| "肉鸽""结局""集成战略"关键词缺失 | 意图关键词词库不完整 | 新增映射→chapter_summary |
| 界园肉鸽答成银凇止境(IS4) | LLM 返回"探索者的银凇止境"作为 canonical_entity | LLM 章节名幻觉过滤：章节名不在问题中的自动降为 expansion_hints |
| expansion_hints 混入路由实体 | `entities = canonical + expansion_hints` | expansion_hints 仅用于 wiki 补充搜索，不参与路由决策 |
| concept_definition 强制 complex | 简单概念如"源石是什么"不需要多步检索 | concept_definition 不再强制 complex |
| 多实体阈值过于激进(>1) | 2 个实体就被迫走 complex | 提升至 >3 |

### P2 改善项

| 缺陷 | 修复 |
|------|------|
| 章节总结事件堆砌无叙事逻辑 | SYNTHESIS_PROMPT 强化"起因→经过→转折→高潮→结局"叙事弧线规则 |
| "凯尔希通过实验复生"vs"石棺复生"事实争议 | 来源忠实度规则新增"不自行补充具体方式/机制""不添加资料中没有的数字" |
| 文本截断过短(500-800 chars) | 提升至 1000-2000 chars |
| EventStore chapter 双向子串匹配过宽 | 改为精确 `==` 匹配 |
