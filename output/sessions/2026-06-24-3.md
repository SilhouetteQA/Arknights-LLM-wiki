## 关键决策

### 1. 架构选型：方案 C（混合路由 + LangGraph Agent）

```
用户问题 → Query Router (本地规则, simple/complex)
  ├─ simple → SimpleSearch (4层检索 → LLM 直接回答)
  └─ complex → LangGraph ReAct Agent (7 tools, 多步检索 → synthesize)
     → 统一 SSE 流式输出
```

### 2. 不引入 LangChain，仅用 LangGraph

LangChain 的 `create_react_agent` 底层就是 LangGraph，直接用 LangGraph 更灵活。Retrieval 层不是标准 Document/VectorStore 模式，不需要 LangChain 适配层。

### 3. FAISS 语义检索 + chunk_id 溯源

参照 mrfz 模式：所有 wiki/event/character 内容统一编码为 FAISS 向量，通过 chunk_id 命名约定（`concept:源石`、`character:阿米娅`）追溯到精确实体。BGE-small-zh-v1.5 编码，IndexFlatIP 内积搜索。

### 4. SentenceTransformer segfault 修复

Windows PyTorch 2.11.0 + SentenceTransformer 加载模型时 C 层段错误（不可被 Python catch）。改用 `transformers.AutoModel` + 手动 mean pooling，生成完全相同的 BGE 嵌入。模型通过 ModelScope 下载（HuggingFace 被墙）。

### 5. FP16 在 CPU 上反而慢 9x

CPU 上 FP16 需要额外转换开销。实测 FP32: 23s/128条，FP16: 214s/128条。最终使用 FP32，全量 6666 条编码耗时 ~43min。
