# 会话总结 — 2026-06-20 (Pass 2 需求澄清 + Spec 产出)

## 任务

Pass 2 实体/关系提取的前期工作：brainstorming + grill-with-docs + 单次出场 NPC 清单 + Spec 产出。

## 关键决策

### Pass 2 范围收敛
- **不做全量关系提取**：敌对/同盟/友谊/师徒等动态关系不提取，通过 participated_events 隐式表达
- **不做 IS 子页面**：用户明确 no longer needed
- **聚焦角色 Wiki 页面生成**：概念/地点 Wiki 后续阶段处理，角色优先

### 提取策略
- **方法 3（先聚合再提取）**：角色在 Pass 1 所有出场聚合后一次 LLM 调用
- **所有角色统一质量**：不因出场少而降级，全部传入完整事件列表 + 原文
- **不打包**：单章角色也独立调用（输入量自然小），避免 JSON 解析风险

### Schema
- summary 为核心字段，按出场章数设字数上限（500/350/250/150/100 字）
- 琐碎对话不出现在 events 但信息需吸收到 summary
- power_level 采用九级社区体系：战场中坚→军事精锐→大国将军→传奇英雄→王庭之主→神明碎片→崛起之物→文明之敌→灭世灾厄，每级 4 子级
- participated_events 由 LLM 自行合并同战役多阶段，只保留大型事件
- 去掉 type / line_range（聚合后不再精确指向单处原文）

### NPC 清单处理

- 发现角色名规范化问题：Pass 1 participants 自由文本导致同角色多名字（陈晖洁/陈、Rosmontis/迷迭香）
- Pass 2 需预处理做角色名规范化
