# 会话总结 — 2026-06-27-1 (Agent Persona 重写 + QA 缺陷发现)

## 任务

用户反映前端测试效果不好，包括：路由/实体查找问题、相变临界回答混乱、风格不喜欢。通过三轮 persona 迭代定位核心问题，最终转向百科编纂者风格。同时建立前端 QA 日志机制发现三个系统性缺陷。

## 关键决策

### 1. Persona 三轮迭代

| 轮次 | 风格 | 用户反馈 |
|------|------|----------|
| #1 CASUAL | "朋友聊天补课" — 口语化、先核心答案再展开 | 不适合讲述性质，复杂问题回答太简短 |
| #2 知识解说 | "介于朋友聊天和百科解说之间" — 自然口语 | 不喜欢，需要更偏百科全书 |
| #3 百科编纂者 | 准确、逻辑严密、行文有前後逻辑脉络 | 当前版本，待验证 |

**最终 persona 特征**：
- 角色：剧情百科编纂者
- 行文：句子段落间自然衔接，按逻辑结构组织
- 结构：剧情按时间线/因果链，概念从定义到展开，角色从概括到细节
- 禁止：口语闲聊、碎片罗列、分点列表
- 来源约束：保持不变（上次验证通过）

### 2. 前端 QA 日志机制

在 `server.py` 中添加 `_log_and_stream` 包装器，每次 SSE 对话自动写入 `output/qa_log.jsonl`，包含：timestamp / question / route_complexity / route_intent / route_entities / route_reason / answer / sources

### 3. 三个系统性缺陷发现

通过前端 5 个实际提问发现：

1. **实体提取噪声** — `_extract_entities_local` 从 WikiStore 匹配过多弱相关实体（如"相变临界"匹配到"罗德岛""乌萨斯""切尔诺伯格"），导致多实体→强制 complex 路由
2. **search_dialogue 工具崩溃** — `'list' object has no attribute 'get'`，在 4 个问题中连续崩溃 5 次
3. **意图分类缺关键词** — "肉鸽""结局""集成战略"未映射到 list_enumeration
