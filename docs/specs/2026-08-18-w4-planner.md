## 1. 背景与目标

### 1.1 背景

当前 complex 问题走 LangGraph ReAct 循环（`graph.py`）：LLM 每步"观察→决策→调工具"，
规划是**隐式**的——步骤数量、顺序、工具选择由 LLM 现场决定，不可控、不可复现，且容易
中途迷失（多跳问题检索方向漂移）。升级方案 §4 要求：复杂问题经显式 Planner 拆解为任务图
（并行/串行执行 + 结果聚合），U-06 规则明确"禁止无规划的隐式多步推理"。

### 1.2 目标

1. `arknights_wiki/agent/planner.py`：LLM 将复杂问题拆解为**任务图**（任务列表 + 依赖 + 工具需求），
   失败时按 `question_type` 规则模板兜底
2. 任务执行器：按依赖拓扑**串行**执行子任务（工具调用，复用 W2 恢复链 + W3 MCP 双轨），结果聚合
3. complex 路径由 ReAct 切换为 **Plan → Execute → Synthesize**；`ARKNIGHTS_AGENT_MODE=react` 可回退
   ReAct（A/B 评测用）
4. 任务图与每步执行在 Langfuse trace 可见（`node_type=planner` 已预留）
5. 评测：10 题 complex 子集对比基线（w2 内部函数 0.936 / w3 MCP 0.967）；用户自测问题单独验证

## 2. 现状分析

- 现有 complex 路径：`graph.py build_agent_graph()` = `call_model ⇄ tool_node` ReAct 循环（≤8 次）+ `synthesize_node`
- 检索工具：`tools.py TOOL_EXECUTORS` 8 个（`ARKNIGHTS_USE_MCP=1` 时切 MCP 后端）
- 恢复链：`resilience.execute_with_resilience`（W2，工具执行通用）
- trace：`schema.py` 已预留 `NODE_TYPE_PLANNER="planner"`（W1）
- 评测对象：benchmark 100 题中 **62 道 complex**（含 10 道多跳/时间线类）
- 现有 complex 基线：10 题 character_complex 子集 — 内部函数路径 0.936 / MCP 路径 0.967

## 3. 技术方案

### 3.1 任务图模型（planner.py）

```python
class TaskNode(TypedDict):
    id: str              # "t1", "t2"...
    description: str     # 任务描述（供 LLM 阅读/合成阶段引用）
    tool: str            # 工具名（TOOL_EXECUTORS 中注册名）
    args: dict           # 工具参数
    depends_on: list[str]  # 依赖的任务 id（空 = 无依赖）
    # 执行期填充:
    status: str          # pending / done / failed / skipped
    result: str          # 工具返回文本（截断）
```

- **LLM 规划**：`plan_tasks(question, route) -> list[TaskNode]` 调 `chat_completion`
  （复用统一入口，自动带重试 + trace），prompt 要求输出 JSON 任务数组（含 description/tool/args/depends_on），
  **工具名白名单校验**（必须 ∈ TOOL_EXECUTORS，防幻觉）+ 任务数上限（≤6）+ 循环依赖检查
- **规则模板兜底**：LLM 失败/超时/校验不过时，按 `route.question_type` 套模板：
  | question_type | 模板 |
  |---|---|
  | comparison | 查实体A、查实体B、查A×B相关事件、综合 |
  | list_enumeration | 查实体、查事件（宽搜）、综合 |
  | causal_reasoning | 查实体、查时间线、查相关事件、综合 |
  | chapter_summary | 查章节摘要/事件、查关键实体、综合 |
  | 其他/多实体 | 逐实体查页面 + 事件 + 综合 |
- 模板也用于生成"plan_tasks 的默认结果"（LLM 未启用时纯规则可用）

### 3.2 任务执行器（executor，并入 planner.py 或 graph.py）

```python
def execute_task_graph(tasks: list[TaskNode], question: str) -> list[dict]:
    # 1. 拓扑排序（按 depends_on；含循环/未知依赖则忽略依赖按序执行）
    # 2. 串行执行：对每个任务调 TOOL_EXECUTORS[tool](**args)（经 W2 恢复链 + W3 MCP 双轨）
    #    （execute_with_resilience 与 _execute_tool_traced 复用 graph.py 现有实现）
    # 3. 结果聚合为 collected_docs 结构（tool/args/result），供 synthesize 使用
```

- **串行执行**（本窗口）：任务数 ≤6，串行已足够；并行预留接口（TaskNode 无依赖可并行，
  后续窗口/需求再启用）
- 失败策略：单任务失败不中断整图（结果标记 failed，synthesize 用可用证据）——体现部分失败处理
- 超时/重试：复用 `_execute_tool_traced`（含 tool_call span + W2 恢复链 stats）

### 3.3 图接入（graph.py）

新增 `build_planner_graph()`：

```
START → plan_node → execute_node → synthesize_node → END
```

- `plan_node`：调 `plan_tasks`，任务图写入 state（`tasks` 字段），span name=`planner`、
  metadata 含 `node_type=NODE_TYPE_PLANNER`、任务数、LLM/rule 来源
- `execute_node`：`execute_task_graph`，每个任务执行包 `tool_call` span（复用现有逻辑），
  聚合结果写入 `collected_docs`
- `synthesize_node`：复用现有实现（证据 → LLM 综合回答）
- **路由切换**：`server.py` complex 路径按 `ARKNIGHTS_AGENT_MODE`（默认 `planner`；`react` 回退
  现有 `build_agent_graph`）——双轨可 A/B，与 W3 MCP 模式一致

### 3.4 trace 埋点（U-04）

| 节点 | name | 记录 |
|------|------|------|
| 规划 | `planner` | node_type=planner、n_tasks、source(llm/rule)、latency |
| 任务执行 | `tool_call`（复用） | tool、args、retries/breaker/fallback（W2）|
| 综合 | `synthesize`（复用） | model、tokens、cost |

### 3.5 评测（U-03）

- 基线：w2_regression（内部函数 0.936）/ w3_mcp（MCP 0.967）同 10 题
- Planner 路径跑同一 10 题子集（`ARKNIGHTS_AGENT_MODE=planner` 默认）→ 对比
  - 达标：overall ≥ 基线 - 0.03；目标：多跳/时间线类有提升
- **用户自测**：用户提出若干问题，分别走 ReAct 与 Planner 路径对比效果（人工评估）

## 4. 验收标准（对齐路线图 W4）

1. `plan_tasks` 对示例问题（"分析凯尔希与罗德岛的历史关系并整理时间线"）输出 ≤6 任务、
   工具名全部合法、无循环依赖；LLM 失败时规则模板兜底可用
2. complex 真实问答走 Planner 路径正常产出（trace 可见 planner → tool_call×N → synthesize）
3. 10 题子集 Planner 路径 vs 基线（0.936/0.967）无显著回落（≥ -0.03）
4. 用户自测问题 ReAct vs Planner 对比有结论
5. `ARKNIGHTS_AGENT_MODE=react` 回退 ReAct 行为不变；全量 pytest 无新增失败

## 5. 风险与取舍

| 风险 | 影响 | 缓解 |
|------|------|------|
| LLM 规划产出非法任务图（幻觉工具名/循环依赖） | 执行失败 | 白名单校验 + 上限 + 循环检测 + 规则兜底 |
| Planner 一步拆解遗漏检索方向 | 回答不全 | 规则模板按 question_type 覆盖典型多跳；任务描述进 synthesize 证据 |
| 任务图固定后不如 ReAct 灵活 | 偶发问题需要现场探索 | 模板含"补充探索"任务兜底；评测 A/B 验证，若回落保留 react 默认 |
| 串行执行耗时（任务 ≤6） | 延迟增加 | 任务数上限 6；每任务复用恢复链；并行留接口 |
| LLM 规划额外成本 | 每 complex 题 +1 次 LLM 调用 | 复用 chat_completion（小 max_tokens），规则兜底可省 |

## 6. 范围外

- Planner 跨请求记忆复用（W6 已跳过）
